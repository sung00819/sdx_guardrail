## p1 에 없는 것 (p2 에서 넣을 것)

### 1. 파레토 후보 풀 (제일 큰 차이)
p1 은 **최고 뱅크 하나**만 이어서 고친다(언덕 오르기). 그래서 한 셀에서는 좋아지고 다른 셀에서는 나빠지는 후보가 버려지고, 한 방향으로만 수렴한다.

- 풀 = 검증 세트를 전부 돈 뱅크들. 각 뱅크에 **인물별 점수**(28명 × 2표본의 평균 R)를 저장한다.
- 프런티어 = 어떤 인물에서든 최고 점수(허용 오차 ε 안)를 낸 뱅크들.
- 부모 고르기 = 프런티어에서 **최고를 낸 인물 수에 비례**해 추첨한다.
- 풀에 넣는 조건: 미니배치를 통과하고 검증을 돈 뒤, 프런티어에 들어가면 넣는다(평균이 최고일 필요는 없음).
- 최종 뱅크 = 풀에서 검증 평균 R 이 가장 높은 것 (T1 조건 아래).

잡음 대책: 한 인물에 2표본이면 R 이 많이 흔들린다 → ε = 0.1 정도로 두고, 프런티어 크기에 상한(예: 8)을 둔다.
인물 단위가 너무 흔들리면 **셀 단위(7개)** 로 바꾼다. 셀 단위는 프런티어가 작고 안정적이지만 다양성은 줄어든다.

### 2. 병합(merge)
뱅크가 조각 단위라 GEPA 병합이 아주 자연스럽다.
- 프런티어에서 공통 조상이 있는 두 뱅크를 고른다. 각 조각은 **조상에서 바뀐 쪽**을 가져간다(둘 다 바꿨으면 검증 점수가 높은 쪽).
- K 반복마다 한 번(예: 4), 반성 없이 미니배치 → 검증으로 같은 관문을 지난다.
- 예: 계보 1이 urgent 를, 계보 2가 support 를 고쳤으면 합친 뱅크는 둘 다 고친 상태가 된다.

### 3. 피드백 텍스트 보강
지금 발화 발췌에 붙는 것은 위반과 state_why 뿐이다. 여기에 더한다:
- 품질 축 체크리스트에서 실패한 항목 (A1·A3·A6b 등, judge 결과의 이유 문장)
- 턴 사실(facts) 중 해당 조각과 관련된 것 (예: means 조각 → `asked_means_access` 가 없었다)
- (4번을 하면) **어느 베이스 LLM 에서 실패했는지**

### 4. 베이스 LLM 여러 개로 평가 (F7)
- 미니배치와 검증을 베이스 2개로 돈다. 예: Qwen3-8B + 다른 계열 8B 급 하나.
- 파레토 단위를 (인물 × 베이스) 로 둔다 → 한 모델에만 맞춘 문구는 프런티어를 독점하지 못한다.
- 마지막 test 에는 **최적화에 안 쓴 베이스**를 하나 넣어 "재학습 없이 다른 LLM 에 적용"을 직접 보인다.
- 비용이 두 배다. 서버 여유를 보고 정한다.

### 5. 하드 제약
- 후보의 검증 T1 비율이 부모보다 높으면 R 과 상관없이 탈락시킨다.
- 뱅크 전체 길이에 상한을 둔다 (조각별 1.5~1.8배 상한은 이미 있다. 그런데 반복하면 전체가 계속 길어진다 → 8B 가 긴 지침을 무시했던 문제).

## 반복 한 번 (p2)

```
1. 프런티어에서 부모 추첨 (최고를 낸 인물 수에 비례)
2. 부모의 검증 대화로 blame → 조각 추첨 (p1 과 같음, tabu 유지)
3. 반성 → 후보 2개 (피드백 보강판)
4. 미니배치: 부모 vs 후보 (같은 인물) → +margin 통과한 것만
5. 검증 (인물별 점수 저장) → 프런티어에 들면 풀에 추가 (T1 제약)
6. K 반복마다: 병합 후보 1개 → 4·5 와 같은 관문
```

비용: p1 과 거의 같다. 미니배치·검증 크기가 같고, 바뀌는 건 부모를 고르는 방식과 병합 한 번뿐이다. 베이스를 2개로 하면 두 배가 된다.
